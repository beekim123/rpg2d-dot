# 音乐与音效

## 1 原则【定】

- **所有声音都由仓库里的代码合成**。源数据是文字（音符、音色参数、包络），不用录音、不用外部采样、不用任何 AI 音乐 / 语音服务、不用现成旋律。
- 合成必须**确定性**：同一份源数据，每次合成的结果逐样本一致（噪声用带种子的伪随机数）。
- 可以参考 ele-pushbox-arts 的 `docs/design/audio.md`：它用仓库内的小型确定性合成器、明确命名的参数和音符数组来做芯片音效，并且用数值标准（响度、峰值、循环接缝）做自动检查。本作沿用这个思路，但风格要更有冒险感和战斗的力量。

## 2 技术方案【建议】

**问题**：20 首曲子都渲染成 WAV 提交进仓库，体积会非常大。

**推荐做法**：一套合成引擎，两处运行。
- **浏览器里**：游戏加载时用合成引擎把需要的曲子 / 音效渲染成音频缓冲（可以放在 Worker 里，渲染完缓存起来），然后正常播放。仓库里只存文字源数据，体积很小。
- **Node 里**：同一套引擎离线渲染成 WAV，用于工作台试听和自动检查（响度、峰值、接缝）。这些 WAV 放在被忽略的缓存目录，不提交。
- 短音效如果更方便，也可以直接渲染成小 WAV 文件提交。

开发者也可以选别的方案（比如运行时用 Web Audio 节点实时合成），只要满足第 1 节的原则。

## 3 音色【建议】

整体是"温暖的芯片音乐 + 奇幻冒险感"。可用的合成手段：

| 音色 | 做法 | 用途 |
|---|---|---|
| 柔和方波 / 脉冲 | 占空比 12.5% / 25% / 50%，经过低通 | 主旋律、琶音 |
| 三角波 / 正弦 | — | 低音、笛子感的旋律 |
| 锯齿 + 低通 + 失谐 | 两三个略微失谐的锯齿波 | 铺底、弦乐感 |
| 拨弦 | Karplus-Strong（带种子的噪声激励，确定性） | 竖琴、鲁特琴、吉他感 |
| 简单 FM | 两个算子 | 钟、铃、玻璃、星光 |
| 噪声 + 滤波 | 带种子的白噪声 / 周期噪声 | 鼓、沙沙声、风、浪 |
| 混响 / 回声 | 简单的多抽头延迟或梳状滤波 | 空间感（迷宫、星坠之渊） |

## 4 主题动机【建议】

全游戏有一段**主题动机**"星之歌"（4 小节），所有曲子都是它的变奏或者包含它的片段，听得出是同一个世界。

动机要求：
- 第一句就要好记，能哼出来。
- 开头上行（像抬头看星星），结尾停在一个"没说完"的音上（悬而未决）。直到最后一首"满天星"才第一次完整地落到主音上。
- 必须原创，开发者自己作曲。写完后在 `audio/` 里附一份简谱或音名说明。

## 7 规格与检查【建议】

| 项 | 要求 | 怎么检查 |
|---|---|---|
| 采样 | 44.1 kHz，单声道（音乐可以立体声） | 离线渲染时读取 |
| 峰值 | ≤ −1 dBFS，无削波 | 离线渲染后计算 |
| 响度 | 音乐循环 RMS 约 −20 dBFS（±2）；音效活跃段 RMS 约 −18 dBFS（±3），同类音效之间差距不超过 3 dB | 离线渲染后计算（报告里叫 RMS，不冒称 LUFS） |
| 循环 | 曲子按小节循环，接缝处无爆音 | 比较首尾样本和斜率 |
| 同时发声 | 音效最多同时 6 个，同一个音效有最小间隔 | 播放器逻辑 + 单元测试 |
| 切换 | 曲子之间交叉淡化 0.5–1 秒；胜利等短乐句压低背景音乐 | — |
| 确定性 | 同一源数据渲染两次，结果逐样本一致 | 测试 |

数值检查通过不等于好听。开发者每完成一首曲子，要在工作台里自己完整听几遍（能听的话），并在 `docs/plan/progress.md` 写下这首曲子的设计说明。用户的听感意见优先。
