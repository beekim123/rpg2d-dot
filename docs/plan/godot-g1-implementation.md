# Godot G1 探索闭环实施

日期：2026-10-25。前置：目录管理16fa889已通过本机完整检查及Linux CI。G0只是原生地图起点；本计划不将网页历史功能计为Godot完成。

## G1a：五图与出入口

- 内容登记表明确测试地图与序章五图的逻辑ID和源路径；同步器消费登记表，运行时只消费资源服务。
- 独立于Node/纹理的世界数据层负责地图结构、显隐条件、碰撞、可达性、双向出口及安全落点。拒绝坏数据时保留旧状态。
- 原生世界场景负责渲染和输入：按地图terrain绑定选择木地板/墙/麦田，切图时清除旧节点和图块，保持整数坐标与脚点排序。
- 小于视口的室内地图居中；大地图按边界跟随。真实走到门格后换图，落在对应门内侧，避免来回自动触发。
- 验证：五图白天/天亮旗标的出生点与必要交互可达；所有门可来回；坏出口不换图。原生与导出Web各走一遍家→镇→灯铺→镇。

## G1b：对话、调查与剧情旗标

- 对话使用原生Control、中文像素字体、头像、逐字/快进/确认；玩家在对话时不能移动。
- 台词与脚本在content里，游戏规则不包含文字或美术路径。先接安全的村民交谈/调查，不提前声称完整序章剧情已可玩。
- 显隐变化不得把玩家夹入实体或堵住必需出口；脚本事务在可安全提交时才生效。

### G1b 本轮落地接口

- 内容：`content/story/lantern-vale.json`，沿用say/set/if/end四种指令；台词仅在中文表，新增记忆只写seen.*，不提前推进序章主线。registry.stories登记脚本包，资源服务合并并拒绝重复ID。
- 规则：StoryRules.configure(scripts,words,portraits)原子校验；run(script_id,flags,cursor)执行到say/end，返回独立flags/pc/line，异常和100条预算耗尽均保留输入。
- 世界：interaction_target按面对的一格与实体占地选目标；validate_position复查旗标布局、玩家安全及当前点到必经交互/出口的路线。事务通过前不写世界状态。
- 界面：独立DialogueBox接收字体、面板、头像、姓名和文字，通过信号请求下一句；父场景将独立组件放在6,174，组件尺寸468×90，为姓名、48px头像、最多3行12px文字和按键提示保留空间。这是对09-ui-ux建议高度的调整，避免裁掉正文。
- 输入：Z/空格/回车交互和继续；未显示完整时先快显；X仅快显本句；鼠标点对话框等同确认。对话期间锁定移动与外部切图，结束恢复输入。
- 验证：纯规则红绿测试、原生控件字数/行数/点击测试、真实场景交谈和重复对白、坏旗标不落地、Web键盘与鼠标对话截图。任何脚本/姓名/头像/文本缺失均使内容检查失败。

## G1c：灯柱与存档

- 原生灯柱点亮反馈与持久化，三手动槽/一自动槽，版本字段/非法输入处理与JSON导出导入。
- 跨图保存角色位置、灯柱与旗标；读取失败保留当前存档，旧版本转换有夹具。
- 自动路线和真实浏览器完成起点→交谈→点灯→切图→保存→读取，才关闭G1。

执行人：当前开发代理；按小步测试/截图/记录/提交顺序进行。当前无需用户操作。

G1b接入已通过原生与Web验证。关键补测包括：坏脚本事务恢复输入、NPC在玩家当前格出现时拒绝、每个可见调查/对话入口实际可达、觉醒后缇娅复访走真实黎明实体、导出网页中的对话框位置与鼠标命中。

## G1c 实施约定（2026-10-25）

- 存档域独立为SaveCodec/SaveStore：version3沿用网页v2的可序列化字段，保留位置/朝向、flags、全局lamp IDs、steps、inventory及空队伍布局；v0/v1/v2有显式转换。非空队伍/NPC移动布局目前不加载，返回清晰错误并保留原文件，不静默吞字段，后续队伍系统接入时再扩展。
- JSON最多512000 UTF8字节；验证版本、地图、整数范围、旗标、灯ID/重复、背包、显隐占位、玩家实际落点和必经通路。验证不通过既不改变当前世界，也不写槽文件。
- 原生FileAccess写私有临时文件，flush、读回验证后rename替换固定slot0–3；上一个有效版本留.bak，失败保留原档，测试只用独立临时目录。
- 手动1–3槽只允许在已亮灯柱旁保存，自动0在真实跨图/首次点灯时更新；初始化/同图显隐刷新/底层恢复不会触发额外自动写入；玩家明确读取或导入成功后，由协调器写一次auto作为新的继续位置，避免刷新回到旧记录。若auto写失败，保留已加载状态并明确提示需要手动保存或导出。有有效auto启动恢复；坏auto保留并暂停自动写，直到成功手动保存、加载或导入。
- 首次面对灯柱交互即点亮，播放源图集lit动画并显示短反馈；再次交互开存档面板。当前无战斗体力/营火系统，不能假装已经回复或修行。
- 存档面板有四槽和保存/读取/导出/导入/新旅途/返回，键鼠都可用，覆盖已有手动槽需面板内二次确认；打开菜单或文件选择时锁定地图输入。显示地图、时间和灯数，不显示实现字段。
- Web导入只能由玩家操作触发文件选择器，限制JSON大小并通过Codec校验；导出使用原生JavaScriptBridge.download_buffer。Native用FileDialog。用户文件传输与只读测试桥分开，不提供任意游戏状态JS写入口。
- 所有原生旧测试明确关闭持久化，存档测试独立root；Web测试用隔离browser context，真实下载/文件选择、刷新和新页面验证浏览器持久化。
- 验收：交谈→点灯→保存手动→跨图自动→加载手动→导出→坏文件拒绝→导入→刷新继续；另测坏落点/NPC重叠/旧版本迁移/写失败不毁原档。当前执行人仍为开发代理，无需用户操作。

旧原型lantern.test地图可合法导入但没有序章出口，菜单提供明确的新旅途入口，确认后从芬恩家开始、替换自动档并保留三个手动槽；不静默重定位旧档。

Web实测揭示异步文件同步窗口，存档后端改为单key同步localStorage记录（当前+有效备份一起写），成功提示后立即刷新必须恢复最新记录；原生仍用文件原子替换。规则和导出JSON共用，不额外依赖游戏前端源码。
