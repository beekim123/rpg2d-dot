# M0 · 地基实施计划

**目标**：标题进入灯谷测试地图，移动、碰撞、NPC 对话、点灯、存读档形成可重复验证的完整小循环；工作台展示代码绘制的 PNG 与动画。
**架构**：TypeScript 严格模式，纯逻辑模块产出可序列化状态，Canvas 2D 负责表现。地图和中文文本用 JSON；美术、音频均由本仓库可重复构建。
**技术栈**：Node 22.12+、Vite、TypeScript、Vitest、Playwright。无游戏运行时依赖；固定 60 Hz、480×270、16px 格、整数像素采样。
**设计依据**：`docs/00-vision.md`、`docs/tech/architecture.md`、`docs/art/art-pipeline.md`、`docs/plan/roadmap.md`。用户已授权自主实施，疑问按 `questions.md` 默认方案继续。

## 全局约束

- 不调用图像、音乐、语音生成模型；不使用外部美术音频，字体仅 OFL 并附全套许可证。
- 构建 / 测试顺序执行，每次仅 1 个计算 worker；启动前检查全机进程，数值库线程限制为 1。
- PNG 提交，WAV 缓存不提交，单文件小于 2 MB；不提交 `.local/` 和本机路径。
- 每个功能先写行为测试并见到预期失败，再实现和验证；每批美术要审对照表和游戏截图。
- 不将 M0 管线验收等同于 M1 质量或用户验收。战斗尚未实现时截图矩阵明确标记不适用。

## 1 · 工程与资源基础

- [ ] 工程：`package.json`、TS/Vite 配置、入口、README、CI，Vitest 单 worker。
- [ ] PNG / 美术：`art/lib/`、`art/palette.json`、`art/source/`、`tools/art.mjs`；支持字符精灵与程序画图，输出清单含帧大小、锚点、动画和 SHA-256。
- [ ] 校验：解码 PNG 检查尺寸 / alpha / 调色板；重绘逐字节比较；错误尺寸、颜色、动画引用必须报错。
- [ ] 测试素材：芬恩四方向、霍伯及头像、草土、水、树、木屋和灯柱；图集帧横向排列；清单作为运行时唯一图像入口。
- [ ] 工作台：素材筛选、整数放大、动画播放、调色板；字体复制到 `third_party/fonts/` 并保留许可证。

## 2 · 探索逻辑与表现

- [ ] `src/core/`：固定步进时钟、场景栈、输入动作、版本化游戏状态。
- [ ] `src/systems/`：文本地图解析与合法性检查、移动 / 碰撞 / 跟随、剧情指令（say/move/set/if）、交互与点灯。
- [ ] 先测试：不能穿越水 / 物件 / NPC；成功移动才更新跟随；脚本跳转有界且阻止缺少文本；状态不被无效操作破坏。
- [ ] `src/render/`、`src/scenes/`：清单加载、地形四边自动拼接、镜头约束、对话框头像和逐字显示、可快进。
- [ ] `content/maps/`、`content/story/`、`content/i18n/zh-Hans/`：测试场景，所有玩家文字走表。

## 3 · 存档、声音和工具

- [ ] 存档 API：3 手动 + 1 自动槽，验证版本与地图位置、支持导出 / 导入和旧版迁移，损坏存档给可恢复反馈。
- [ ] 调试：`?map=...&at=x,y`、碰撞显示、传送和重置；非法参数安全回退。
- [ ] 音频：纯 TS 确定性合成 + 中文曲目说明，界面音效和原创测试旋律；44.1 kHz、峰值与 RMS、循环首尾检查；用户手势后播放。
- [ ] 内容检查：地图可达性、素材 / 文本 / 剧情引用、实体唯一性、出口一致性。

## 4 · M0 验收

- [ ] `npm run check` 顺序运行类型、单元测试、内容、美术、音频、构建。
- [ ] 自动路线通过真实逻辑移动到霍伯、对话、点灯、存档、移动后恢复。
- [ ] Playwright 单 worker 从标题进入地图，走动 / 对话 / 菜单 / 存读档，检查控制台错误；截图标题、地图、对话、菜单、工作台。
- [ ] 人工审图记录到 `docs/plan/progress.md`；听感无法直接确认时如实记为未验收。
- [ ] 更新 backlog / 进度 / `docs/v2/status.md`，小步提交并推送；验收条件全部满足才打 `m0` 标签。
- [ ] 然后拆分并开始 M1 灯谷镇正式素材与地图，绝不将测试内容冒充完整序章。
