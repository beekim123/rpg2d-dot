# 代码声音

声音由本目录 `synth.ts` 的纯 TypeScript 合成器产生，浏览器播放与 Node 离线检查使用相同代码。没有录音、外部采样或生成模型；噪声由固定种子的整数伪随机序列产生。正式导出在 `export/`：每个 WAV 小于 2 MB，连同清单提交；体积更大的临时试听仅放 `.cache/`。

## 测试主题「灯前的小步」

这是 M0 的八秒管线测试曲，不作为 M1 正式标题曲验收。C 大调、4/4 拍、120 BPM，共四小节；每个音占一拍。音名中的数字为科学音高记号（中央 C 为 C4）。

```text
旋律：| C5  E5  G5  A5 | G5  E5  D5  E5 | F5  A5  G5  E5 | D5  E5  G5  D5 |
低音：| C3      G3     | A2      E3     | F3      C3     | G2      D3     |
和声：| C 大三和弦      | A 小三和弦     | F 大三和弦     | G 挂留二和弦   |
```

开头 C–E–G 向上展开，末音为上主音 D，不落回主音 C。柔和的奇次谐波主音、正弦低音和轻拨弦琶音构成暖色音色；末小节保留 D 与 A 的悬念，再循环回第一小节。它是独立编写的音符序列，没有引用现成旋律。

界面音使用短音形区分动作：确认上行两音、取消下行两音、脚步为低频短音加带种子噪声、存档为三音铃、拒绝为下坠双音、点灯为上行闪光音。每个声部与整个缓冲都有平滑包络，首尾样本归零，循环接缝的幅度和斜率另行检查。

## 战斗测试主题「星域对决」

`battle_theme` 是战斗表现候选曲，不作为 M1 正式配乐或主观听审通过记录。C 大调、4/4 拍、120 BPM，共八小节、16 秒；以测试主题 C–E–G 上行动机作节奏化变体。音名后的数字为八分音符个数，每小节合计 8；音高仍使用科学音高记号。

```text
| C5×1 E5×1 G5×2 A5×1 G5×1 E5×2 |
| G5×1 E5×1 D5×2 E5×2 G5×2      |
| F5×1 A5×1 G5×2 E5×1 F5×1 A5×2 |
| D5×1 E5×1 G5×2 A5×1 G5×1 D5×2 |
| C5×1 E5×1 G5×1 C6×1 B5×1 A5×1 G5×2 |
| A5×1 G5×1 E5×2 G5×1 E5×1 D5×2 |
| F5×1 A5×1 C6×2 A5×1 G5×1 E5×2 |
| D5×1 E5×1 G5×1 A5×1 G5×2 D5×2 |
和声：C / Am / F / Gsus2，重复两次；末音仍为 D。
```

主旋律使用有限奇次谐波的脉冲音色，第一句以短音起步，后四小节抬高回答；正弦低音用根音、五度和八度保持推进，轻拨弦只补和声。低鼓落在第一、三拍，滤波噪声小鼓落在第二、四拍，短高频帽声填反拍，避免持续嘈杂覆盖技能反馈。所有鼓声均是振荡器与固定种子噪声；整曲仍由同一个纯函数串行生成，缓存后循环，不启动 Worker。

## 战斗事件音效

| cue | 秒 | 声音设计与用途 |
|---|---:|---|
| `battle_hit` | 0.22 | 下坠低音、短噪声冲击和高频脉冲，用于实际命中 |
| `battle_heal` | 0.72 | C–E–A 上行柔铃加低八度铺音，用于治疗 |
| `battle_guard` | 0.48 | G–D 的非整数倍 FM 共振，营造短金属盾响 |
| `battle_cast` | 0.52 | 加速上行的脉冲与末端铃音，用于星术发动 |
| `battle_win` | 1.25 | C–E–G 后到高 D 的短胜利句，保留主题未完的悬念 |

战斗音乐和事件音分别播放；移动、取消、无效操作继续使用原界面音。六个战斗短声均归类为 `effect`，包含胜负短句，不套用音乐循环的 RMS 口径。

## 接口与检查

- `cues`：原 7 个 M0 cue、7 个战斗 cue 与 6 个正式序章曲目 id，共 20 项。`test_theme / battle_theme` 仍是独立测试候选。
- `cueKinds`：每个 cue 的 `music / effect` 分类，供数值检查与测试选择完整循环或活跃段 RMS。
- `cueSampleRates`：20 个 cue 的发行采样率；旧 14 项保持 44100 Hz，新六曲为 22050 Hz。
- `renderCue(id, sampleRate = 44100)`：返回单声道 `Float32Array`；支持 8–96 kHz 整数采样率，输入无效时抛出 `RangeError`。
- 网页参考适配器 `reference/web/src/audio/player.ts` 的 `AudioPlayer.unlock()`：在用户手势中调用以建立和恢复 Web Audio；之后用 `play(id)` 播放音效、`music(id)` 循环曲目、`setMuted(boolean)` 静音。缓冲固定在 44100 Hz 合成，由 Web Audio 重采样到设备采样率（包括 192 kHz）；曲目切换沿用 0.6 秒交叉淡化。
- `npm run audio:check`：双次合成逐样本比较，报告 SHA-256、峰值、RMS 与循环首尾差值 / 斜率；错误时以非零状态结束。
- `npm run test:resources`：合成与播放器纯逻辑调度测试。

RMS 采用振幅平方均值的平方根，明确以 dBFS 报告，不称为 LUFS。音乐使用完整循环缓冲；音效仅裁去首尾低于 −80 dBFS 的样本后测量活跃段。目标为音乐 −20 ±2 dBFS、音效 −18 ±3 dBFS，峰值不高于 −1 dBFS。数值通过不代表听感验收；完整试听仍由能播放音频的工作台与试玩完成。

## 资源与播放器边界

合成器已从原网页源码抽离到本目录，不依赖浏览器、游戏状态或Godot。曲谱和合成参数继续在此维护；参考网页播放器留在 `reference/web/src/audio/`。Godot通过AssetCatalog语义ID读取受管WAV副本；AudioService只负责播放，不包含合成代码、剧情或战斗结算。

## G3 原生播放与受管声音

G3 的 14 个 cue 由 `npm run audio:build` 串行生成 44100 Hz、单声道、PCM16 WAV 和 SHA-256 清单。G4 新六曲采用后文的逐 cue 发行采样率。量化后的真实PCM再检查峰值/RMS和首尾接缝；`audio:verify` 只比较，不修补。`godot:sync` 校验来源哈希、WAV头和逐字节哈希后同步，`godot:verify` 保持只读。未知文件保留，受管路径拒绝符号链接。

Godot默认WAV有损压缩必须关闭（`compress/mode=0`），避免同一素材经过导入后变化。原生测试逐cue比较导入数据与WAV的PCM数据段；音乐只设前向循环，音效不循环。调用者拿到独立播放资源，不能改坏缓存。

AudioService等待第一次真实按键/点击启声；最多6个效果声和2个交叉淡化音乐播放器，不随战斗次数增加。音乐切换0.6秒，静音/失焦/隐藏时立即停止声音，恢复后只重启所请求的音乐。结束/重试清理旧效果声；退出移除自身总线。专用总线限制峰值到−1 dB。Web使用Stream播放，以支持限幅器；保持无线程导出，代价是比Sample模式更高的延迟，依据[Godot Web音频文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#audio-playback)。需在最终试玩中继续检查响应听感。

独立HTML展示器仍内嵌本合成器，不依赖Godot/游戏源码或网络。发行清单存在时，构建会逐字节核对Godot声音副本；浏览器对合成结果应用相同PCM16量化。G3 的 14 项使用44100 Hz缓冲，包含192 kHz设备回归；G4 新六曲的工作台接入须使用 `cueSampleRates[id]` 建立缓冲，再重采样到设备。播放响度由各端播放器控制，各端须使用一致的制作采样率。

以上是 G3 的 14 个 cue 技术接入记录：实际浏览器已测到音频样本、静音归零与恢复，原生86项检查通过。不能把此前候选数值通过等同于下方新曲的正式配乐验收。

## G4 序章六曲谱面

六个正式曲目 ID 现在各有独立谱面与编配；这批是待数值检查、导出检查和主观听审的作曲实现，**尚未主观听审**。旧 `test_theme`、`battle_theme` 的曲谱、合成分支、默认采样率和逐样本输出必须保持不变；不能用改名代替新曲。

全部旋律与和声由本仓库独立编写，没有外部旋律、录音、采样或生成模型。六曲沿用本项目自己的 C–E–G 上行语汇，并把它写成下面四小节“星之歌”。数字是八分音符个数，每小节合计 8，全部为 4/4 拍；`休` 是休止。

```text
A1 | C5×2 E5×1 G5×1 A5×2 G5×2          |
A2 | E5×2 D5×1 E5×1 G5×2 D5×2          |
A3 | F5×2 A5×2 G5×1 E5×1 F5×2          |
A4 | D5×2 E5×1 G5×1 A5×1 G5×1 D5×2    |
```

开头 C–E–G 上行，完整四小节停在 D。正式六曲各自结束时，主旋律仍停 D5，和声留在 G 挂留二和弦或 G–D 空五度，不写终章才拥有的 C 主音完整终止。

| cue / 曲名 | BPM | 调式 | 小节 / 设计时长 | 编配与对比 |
|---|---:|---|---|---|
| `title` / 星之歌 | 84 | C 大调，G 挂留收尾 | 12 / 34.286 秒 | A 四小节用笛子感主音、柔和长音与疏铃；中间四小节让 FM 铃回答，琶音减半；最后四小节变奏再现，延长末尾 D |
| `lantern_vale` / 灯谷镇 | 108 | C 大调 | 16 / 35.556 秒 | A 笛子与拨弦；第二段由拨弦领奏、笛子在句间回答；第三段高音区展开；第四段回到笛子，轻低鼓保留走路感 |
| `festival` / 星落祭之夜 | 132 | C 大调 | 16 / 29.091 秒 | 铃主旋律、上八度拨弦与轻反拍；第二段抬高回答；第三段改笛子、减鼓和琶音；末段铃声再现，保留 D |
| `crisis` / 袭击 | 144 | C 自然小调，G–D 空五度收尾 | 16 / 26.667 秒 | C–降E–G 断奏碎片与低音八分音符；第二段升高；第三段下降一个八度、减鼓留空；最后恢复紧密脉冲，仍不落 C |
| `awakening` / 觉醒 | 120 | C 大调 | 12 / 24 秒 | 第一小节蓄势，1.5 秒出现 C/E 上行，2 秒以 G 回答并进入完整脉冲、低八度和鼓；中段柔和主音回答，末段强化再现 |
| `battle` / 星域对决 | 144 | C 大调 | 16 / 26.667 秒 | 主句改为切分短脉冲；第二段回答；第三段低音区拨弦与疏鼓形成对比；最后加低八度主音与少量高铃，不能与旧 `battle_theme` 混为一曲 |

各曲主要变化段的原创音名如下。它们不是把四小节 PCM 重复拼接；谱面、声部密度、低音进行及配器都会随段落变化。

```text
title，B段首句：
| 休×1 E5×1 G5×2 B5×2 A5×2 |
B段后续以 G–E–D–E、F–A–C6–B–G、A–G–E–D 回答。

lantern_vale，拨弦回答首句：
| 休×1 E5×1 G5×2 E5×1 D5×1 C5×2 |
回答段最后为 E–D–G–E–D；随后以 E–G–C6–B–A 开始高区展开。

festival，减鼓段首句：
| 休×2 G5×1 B5×1 D6×2 B5×2 |
减鼓段依次由 A–E–G–C6–A、F–A–D6–休–C6–A、G–A–G–E–D 回落。

crisis，小调碎片首句：
| C5×1 Eb5×1 G5×2 休×1 Eb5×1 D5×2 |
低区对比段首句为 C4–Eb4–休–G4–Bb4，段尾停 D4；整曲再现后停 D5。

awakening，第一、二小节：
| 休×6 C5×1 E5×1 | G5×2 A5×2 C6×2 B5×2 |
稀疏的首小节只有低音、轻铃和短鼓上行；第二小节已经是完整编配。

battle，节奏主句：
| C5×1 E5×1 G5×1 A5×1 G5×2 E5×1 G5×1 |
第二段以 E–G–B–D6–C6–B 回答；低区对比段以 A4–C5–E5–休–D5 起步。

六曲共同的再现末句：
| D5×2 G5×1 A5×1 D5×4 |
crisis 保留小调版本：| D5×2 G5×1 Eb5×1 D5×4 |
```

音色继续使用有限谐波的暖脉冲、正弦低音、指数衰减拨弦、双算子 FM 铃和带固定种子的鼓。新增笛子感音色以基音、少量二／三次谐波和轻幅度起伏构成，只用于新曲。各声部有平滑起止包络；整曲仍使用既有全循环 RMS 归一化与峰值余量，并令首尾样本归零。目标是 RMS −20±2 dBFS、峰值≤−1 dBFS；这些是待验证要求，不是本节宣称已经通过的测量结果。

### 发行采样率调整【建议】

正式六曲发行采用 **22050 Hz、单声道、PCM16**，旧 14 个 cue 继续 **44100 Hz**。这是对音频方向中默认 44.1 kHz 建议的局部调整：保持按完整小节编曲，同时满足每个发行 WAV 小于 2,000,000 字节。最长的 `lantern_vale` 按设计为 784000 个样本，标准 44 字节 WAV 头加 PCM16 数据预计为 1,568,044 字节；同一曲用 44100 Hz 会超过单文件预算。

`renderCue(id, sampleRate = 44100)` 的默认值仍兼容旧调用，显式采样率继续支持 8000–96000 Hz。发行器和独立工作台应使用 `cueSampleRates[id]` 同时合成及声明音频缓冲的采样率；不能只改 WAV 头。正式六曲的 22050 Hz 样本数依次为 756000、784000、641455、588000、529200、588000；它们是设计长度，发行验证须检查真实 WAV。

新增 `tests/resources/prologue-audio.test.ts` 用此前 G3 验证记录的 14 份 Float32 SHA-256 固定基线保护旧声音；另检查新 ID、每曲发行率、完整小节时长、六曲区别、确定性、RMS、峰值、接缝与觉醒前两秒的进入速度。测试不把当前实现生成的结果作为新期望值。
